# Related Work 起草脚手架

本文件只提供结构、素材映射和自查清单。**正文由标注者本人撰写**：研究稿的文字本身是申请材料，
代笔会让"这个人能不能做研究"这个判断失效。

素材来源：`docs/literature-notes.md`、`docs/literature-and-advisor-match-2026-08.md`。
两份笔记已为六篇论文各写了"事实摘录 / 能抄什么 / 和我差在哪 / 它没解决什么"，本节是把它们
重新组织成一个论证，而不是逐篇复述。

## 这一节要完成的任务

Related Work 不是文献清单，是**一个论证**：读完之后，读者应当自己得出"所以确实需要做这项工作"，
而不是等你在最后一段宣布。

最常见的失败是按论文分段——"X 做了 A。Y 做了 B。Z 做了 C。"——没有综合、没有张力。
**按主题分组，每组落在同一个欠缺上。**

## 建议的四组结构

### 第 1 组：垂域 LLM 能力基准

素材：FinBen、DomainRAG。

这一段要落的点：两者都覆盖广、按能力分解、都把 RAG 纳入评测范围，**但检索层没有被单独诊断**。
- FinBen：RAG 只出现在摘要与引言的创新声明，任务定义与结果没有独立 retriever 配置、
  没有 BM25/Dense 对照、没有 Recall@K/MRR，Regulations 仍是答案级 ROUGE/BERTScore。
- DomainRAG：比较了 closed-book / gold reference / retrieved reference，也观察到实体精确匹配下
  BM25 可强于 BGE——但它是**能力 benchmark**，不是围绕固定语料做检索器与证据坐标的受控实验。

注意：DomainRAG 是人大高瓴的工作，是最贴近的对照。**必须说清区别而不是贬低它**；
你的定位是更窄、更受控，不是覆盖更广。

### 第 2 组：RAG 的生成端评测

素材：RAGAS、Self-RAG。

这一段要落的点：两者都在把"RAG 做得好不好"拆开，但拆的是**生成端**。
- RAGAS：faithfulness / answer relevance / context relevance 都由 LLM judge 给出，无需人工 ground truth；
  代价是 judge 自身有模型与提示偏差，而且"答案忠实于上下文"不等于"上下文召回了完整 gold evidence"。
- Self-RAG：把"是否需要检索、证据是否相关、输出是否受支持"显式拆成不同变量——这个拆分本身值得借鉴；
  但它需要专门训练与 teacher feedback，不是能直接套在任意 API 模型上的方法。

这组的欠缺：**没有字符级 gold evidence，就无法把"没检索到"和"检索到了但没用好"分开归因。**

### 第 3 组：检索侧基准

素材：BEIR。

这一段要落的点：BEIR 在检索侧做到了本项目想要的那种严谨（统一 corpus/query/qrels、
覆盖 lexical/dense/late-interaction/reranking、发现 BM25 是稳健基线且 dense 并非处处胜出），
**但它是通用域，且没有拒答与错误前提这类行为**。

BEIR 关于 **annotation selection bias** 的那条观察要在这里点明并接到自己的方法上：
qrels 常由特定 lexical pool 形成，会系统性不利于非词汇方法。这是你引入
question–evidence 词汇重叠度量与 low/medium/high 配额的**直接理由**，也是你能主张
自己的对比不是标注机制产物的依据。

### 第 4 组：人工事实性标注协议

素材：TreatFact（Factual Consistency Evaluation）。

这一段要落的点：它证明了**细分维度一致率 0.73–0.94、整体单一评分只有 0.55**，
直接支持"不设主观总分、逐维判断"的做法；但它判断的是给定源文档时摘要是否事实一致，
**完全没有检索环节**。

### 收束段：本工作的位置

不要写成"因此我们提出了一个全新的……"。写成**上面四组各自缺的那一块合起来正好是这里做的事**：

1. 冻结语料 + 字符偏移 gold evidence（第 2、3 组缺）
2. 同一批题上隔离比较检索方法（第 1 组缺）
3. 把 refuse 与 correct_premise 作为不同的预期行为分别评（全部四组都缺）
4. 用词汇重叠分层控制 BM25 的构造性优势（第 3 组自己提出但未实施的告诫）

## 自查清单

写完后逐条对照，任何一条不过关就改：

- [ ] 有没有出现连续两段都以论文名开头？有就说明还是按论文分组，不是按主题。
- [ ] 每一组是否都落在**同一个**欠缺上？如果一组里有两个不相干的批评，拆开或删掉一个。
- [ ] 有没有把哪篇论文写成"它没做好"？正确的写法是"它解决的是另一个问题"。
      尤其 DomainRAG——它是目标院校的工作。
- [ ] 每一句关于某篇论文"没有做 X"的断言，能否在该论文正文里指出证据？
      不能就删掉，或改成"论文未报告"。
- [ ] 收束段有没有暗示"前人都没想到"？六篇不是全部文献，这样写会被一眼看穿。
      诚实的写法是限定设定：技术文档场景、这一组特定条件下。
- [ ] 是否声称了实验尚未支持的东西？当前 n=4–18、dev-only、单人标注，
      这一节不能预支 Results 还没给出的结论。

## 不能写的东西

- 不能说"首次"、"据我们所知没有人"——你读了六篇，这个断言的成本远高于收益。
- 不能把 FinBen 或 Factual Consistency 的作者单位写错。前者谢倩倩同时列武汉大学与 The Fin AI；
  后者她列的是 The Fin AI，**不是**武汉大学。这两条在 `literature-notes.md` 里有核实记录。
- 不能引用未经核实归属的论文（DR³-Eval、TELBench、TVIR 存在同名作者风险，见笔记 §同名作者风险）。
