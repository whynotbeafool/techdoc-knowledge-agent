# 标注犹豫日志

标注时任何判断犹豫超过 10 秒，都记在这里。这份日志是修订标注规范的唯一依据。

格式：

```
## q00X
- 问题：
- 当时的选择：
- 犹豫原因：
- 是否需要新增规范条款：
```

---

## q005
- 问题：由一处识别出 `causal confusion`，再用该实体定位后文 §4.8，是否足以算作 `multi_hop`？
- 当时的选择：暂标 `multi_hop`，并将 `annotation_status` 设为 `needs_review`。
- 犹豫原因：两处证据存在明确的检索依赖且跨章节，但最终答案很短；熟悉文档结构的人也可能直接搜索问题中的 “false correlations” 而跳过第一跳。
- 是否需要新增规范条款：待五题复盘。需要决定 multi-hop 判定看“存在必要的信息依赖”，还是看“任何可行检索路径都必须经过第一跳”。

## q002
- 问题：证明一个问题是 `out_of_scope`，需要搜索哪些同义词才算充分？
- 当时的选择：搜索整个五文档语料中的 `etcd`、`encryption`、`cipher` 和独立词 `AES`，均无相关正文命中后标为 `out_of_scope`。
- 犹豫原因：不存在有限关键词集合能严格证明语料没有答案；只搜索问题原词可能漏掉同义表达。
- 是否需要新增规范条款：是。v1 应规定无答案题至少记录检索过的关键词/同义词，并要求人工检查最相关候选段落，而不是把“字符串无命中”当成充分证明。

## q004
- 问题：语义上需要两段并列证据，但在 `chunk_size=800` 时两段恰好进入同一个 chunk，是否仍算 `multi_evidence`？
- 当时的选择：保持 `multi_evidence`。类型描述问题所需的最小证据单元，不绑定某次切块结果。
- 犹豫原因：若用“需要召回几个 chunk”定义类型，同一道题会随 500/800/1500 参数改变类别，导致金标准被实验配置污染。
- 是否需要新增规范条款：是。v1 应明确 reasoning_type 与 chunk 数量正交；multi-evidence 可以被一个较大的 chunk 同时覆盖。

## q005（首次检索实验后补充）
- 问题：Dense@5 只命中 §4.8 的第二条证据，未命中 BC 段落；这是否支持当前 multi-hop 标注？
- 当时的选择：保留 `needs_review`，不因一次检索结果反向修改金标准。
- 犹豫原因：结果符合“单次 dense query 难以覆盖两跳”的预期，但标注类型必须由问题的信息依赖决定，不能用某个基线失败来证明。
- 是否需要新增规范条款：无需新增；作为禁止用实验结果反向污染真值的实例保留。

## q016
- 问题：先根据“整段输出共用同一检索文档”识别 `RAG-Sequence`，再用该变体名连接其 Open MS-MARCO NLG 结果，是否构成必要的 `multi_hop`，还是两个答案成分的 `multi_evidence`？
- 当时的选择：标为 `multi_hop`，并将 `annotation_status` 设为 `needs_review`。
- 犹豫原因：行为描述到实验结果之间必须通过中间实体 `RAG-Sequence` 连接，符合 §5 的依赖定义；但第二段也直接重复了该实体，两段可逆序阅读，边界仍值得盲化复标。
- 是否需要新增规范条款：暂不新增；现有“中间实体是否为连接第二处证据所必需”的规则已覆盖，留待复标检验其可操作性。

## q017
- 问题：从“两套交互文档的共同基础”识别 `OpenAPI schema`，再连接其检查端点和内部数据模型标准，是否属于 `multi_hop`，还是三段并列证据？
- 当时的选择：标为 `multi_hop`，并将 `annotation_status` 设为 `needs_review`。
- 犹豫原因：问题没有直接给出 `OpenAPI`，后两项答案都需要先由第一段得到这一中间实体；但最终答案的端点与 JSON Schema 也可视为两个并列成分，需在复标时检验依赖判据是否稳定。
- 是否需要新增规范条款：暂不新增；沿用 §5 的“问题是否已给出第二跳所需实体”判据，留待盲化复标。

## q017（复核时补充：分类学缺口，与标签取值无关）
- 问题：q017 的最小充分证据集拓扑是 e001 →｛e002, e003｝——先经一跳得到 `OpenAPI schema`，
  第二层的检查端点与 JSON Schema 之间没有依赖、可任意顺序读取。现有三分类
  （single_evidence / multi_evidence / multi_hop）表达不了这种"一跳之后并列展开"的混合拓扑。
- 当时的选择：按 §5 的字面规则保持 `multi_hop`（存在必要依赖即归此类），不改分类学。
- 犹豫原因：`multi_hop` 这个标签丢掉了"第二层是并列的"这一信息，而它直接决定单题
  Evidence Recall@1 的结构上限——q017 有 3 条证据，上限 0.333；q005 与 q016 各 2 条，上限 0.5。
  三题同属 `multi_hop` 却有不同的结构天花板，按 reasoning type 做宏平均时并不可比，
  §6.1 关于"不得脱离题型构成解释 Recall@1"的告诫在类内同样成立，但目前无字段可承载这一区别。
- 是否需要新增规范条款：v2 再议，现在不动。此刻修改分类学会使已标注的 9 题全部需要复核，
  代价大于收益。v2 可考虑的方向：记录证据条数或拓扑形状（chain / fan-out），
  使 Recall@1 的结构上限可由字段推出，而不必逐题回看证据。
